# Kaspi Учёт

Веб-приложение для учёта поступлений и расходов **Kaspi Магазина** и **Kaspi Pay**.
Работает в браузере на телефоне и компьютере, данные общие для двух пользователей,
есть выгрузка в Excel и загрузка из вашей текущей таблицы.

## Возможности
- Продажи (канал Магазин / Pay, комиссия, доставка, пакет, этикетка — «чистыми» считается само), расходы, снятия, пополнения.
- Обзор: выручка, чистыми, расходы, прибыль и маржа, сравнение с прошлым периодом, графики, каналы, расходы по категориям, помесячная таблица, расчётный остаток.
- Два пользователя с отдельными паролями; у каждой записи видно, кто её внёс/изменил; журнал изменений.
- Изменения одного пользователя появляются у другого сами (опрос раз в 8 секунд).
- Excel: листы «Операции» (фильтры, формулы), «По месяцам», «Расходы по категориям».
- Импорт вашего `.xlsx` (предпросмотр, без дублей при повторной загрузке).
- Устанавливается на экран телефона (PWA), тёмная тема.

## Запуск локально
```bash
npm install
npm start          # http://localhost:3000, тестовые пользователи demo1/demo1 и demo2/demo2
npm test
```

## Настройка
| Переменная | Назначение |
|---|---|
| `APP_USERS` | **обязательна в продакшене**: `Имя1:пароль1,Имя2:пароль2` (без запятых в паролях) |
| `DB_FILE` | путь к файлу SQLite (по умолчанию `data/kaspi.db`, в Docker `/data/kaspi.db`) |
| `PORT` | порт (по умолчанию 3000) |

## Развёртывание (чтобы открывать с любого устройства)
Нужен хостинг с **постоянным диском** (иначе база сотрётся при перезапуске) и HTTPS — например Render, Railway или Fly.io:
1. Создайте сервис из этого репозитория (используется `Dockerfile`).
2. Подключите постоянный том к `/data`.
3. Задайте `APP_USERS`, например `Руслан:надёжныйПароль1,Партнёр:надёжныйПароль2`.
4. Откройте выданный адрес на телефоне и компьютере, войдите.

**Резервная копия:** база — один файл `/data/kaspi.db`; копируйте его регулярно, плюс всегда можно выгрузить Excel.

## Ограничения
- Нужен интернет (без сети откроется оболочка, но данные не загрузятся и не сохранятся).
- Остаток по счёту расчётный (продажи чистыми + пополнения − расходы − снятия); начального остатка нет.
- Одновременное редактирование одной записи: побеждает последнее сохранение.
