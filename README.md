# Kaspi Учёт

Веб-приложение для учёта поступлений и расходов **Kaspi Магазина** и **Kaspi Pay**.
Работает в браузере на телефоне и компьютере, данные общие для двух пользователей,
есть выгрузка в Excel и загрузка из вашей текущей таблицы.

## Возможности
- Продажи (канал Магазин / Pay, комиссия, доставка, пакет, этикетка — «чистыми» считается само), расходы, снятия, пополнения.
- Обзор: выручка, чистыми, расходы, прибыль и маржа, сравнение с прошлым периодом, графики, каналы, расходы по категориям, помесячная таблица, расчётный остаток.
- Два пользователя с отдельными паролями; у каждой записи видно, кто её внёс/изменил; журнал изменений.
- Изменения одного пользователя появляются у другого сами (опрос раз в 8 секунд).
- Excel: листы «Операции» (фильтры, формулы), «По месяцам», «Расходы по категориям».
- Импорт вашего `.xlsx` (предпросмотр, без дублей при повторной загрузке).
- Устанавливается на экран телефона (PWA), тёмная тема.

### Автоматизация (вкладка «Авто»)
- **Kaspi Магазин → продажи сами.** Сервер раз в 30 минут забирает завершённые заказы через официальный API Kaspi (нужен `KASPI_TOKEN`). Отменённые не вносятся; если уже внесённый заказ потом вернули — запись помечается для проверки, а не удаляется молча.
- **Откуда комиссия.** Приложение её не «знает»: Kaspi задаёт ставку для каждой *категории* товара, а в API заказов поля комиссии нет. Поэтому вы один раз задаёте ставку по категории (так, как она выходит в вашем отчёте Kaspi), и продажи этой категории считаются сами. Где ставки нет — комиссия и доставка подбираются по ближайшим по сумме продажам из вашей же истории (минимум 3 похожих, иначе ничего не придумывается).
- **«≈ приблизительно».** Всё подобранное автоматически помечено ≈ и не смешивается с фактом, пока не сверено.
- **Сверка с выплатой.** Ввели сумму, которую Kaspi реально перечислил за период, и комиссия/доставка у «≈»-продаж подгоняются так, чтобы итог совпал до копейки. Вручную сверенные продажи не меняются.
- **Регулярные платежи** (налог, соцотчисления, абонплата): на главной «К внесению», вносится одним нажатием; повторы в том же месяце невозможны. Предлагаются автоматически по вашей истории.
- В форме комиссия и доставка подставляются сразу после ввода суммы; «Повторить» копирует операцию на сегодня.

**Kaspi Pay:** публичного API для выписки у Kaspi нет (только ручная выгрузка из кабинета), поэтому для него — ввод с подсказками и сверка. Неофициальные обходы не используются.

## Запуск локально
```bash
npm install
npm start          # http://localhost:3000, тестовые пользователи Руслан / demo1 и Айгуль / demo2
npm test
```

## Настройка
| Переменная | Назначение |
|---|---|
| `APP_USERS` | **обязательна в продакшене**: `Имя1:пароль1,Имя2:пароль2` (без запятых в паролях) |
| `KASPI_TOKEN` | токен продавца Kaspi Магазина для автосинхронизации (как получить — «Как получить токен авторизации в Магазине на Kaspi.kz?» на guide.kaspi.kz). Хранится только в переменной окружения |
| `KASPI_SYNC_MINUTES` | как часто проверять заказы (по умолчанию 30) |
| `APP_TZ` | часовой пояс для дат заказов (по умолчанию `Asia/Almaty`) |
| `DB_FILE` | путь к файлу SQLite (по умолчанию `data/kaspi.db`, в Docker `/data/kaspi.db`) |
| `PORT` | порт (по умолчанию 3000) |

## Развёртывание на Cloudflare (бесплатно, рекомендуется)
Приложение работает целиком на Cloudflare Workers: данные хранятся в SQLite внутри Durable Object, отдельная база и сервер не нужны, сервер не «засыпает», а раз в 30 минут (если задан токен) подтягиваются заказы Kaspi.

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/Ruslan-Imakanov/kaspi/tree/claude/kaspi-analytics-app-p3un2a)

1. Нажмите кнопку, войдите в Cloudflare и разрешите доступ к GitHub (Cloudflare создаст копию репозитория у вас и будет сам пересобирать приложение при каждом изменении).
2. В форме замените значение **APP_USERS** на свои логины и пароли: `Руслан:ВашПароль1,Айгуль:ВашПароль2` (пароль от 8 символов). Пока там пароли-образцы, сайт не запустится — это защита.
3. Нажмите Deploy. Адрес будет вида `https://kaspi-ledger.<ваш-поддомен>.workers.dev`.
4. Позже, когда будет токен Kaspi: Workers & Pages → kaspi-ledger → Settings → Variables and Secrets → добавьте секрет `KASPI_TOKEN`.

Вручную: `npm install`, затем `npx wrangler login` и `npm run worker:deploy`; секреты — `npx wrangler secret put APP_USERS`. Локальная проверка на движке Cloudflare: скопируйте `.dev.vars.example` в `.dev.vars`, `npm run worker:dev`, затем `node scripts/worker-smoke.js`.

Резервные копии: в Cloudflare у SQLite Durable Object есть восстановление на любой момент за последние 30 дней; плюс всегда доступна выгрузка в Excel.

## Развёртывание в Docker (альтернатива)
Подойдёт любой хостинг с **постоянным диском** (иначе база сотрётся) и HTTPS — Render, Railway, Fly.io:
1. Создайте сервис из этого репозитория (используется `Dockerfile`).
2. Подключите постоянный том к `/data`.
3. Задайте `APP_USERS` (и при желании `KASPI_TOKEN`).
Запускайте один экземпляр: база в файле. Копируйте `/data/kaspi.db`.

## Ограничения
- Синхронизация с Kaspi проверена на имитации API в формате JSON:API, а не на живом аккаунте: первый запуск делайте кнопкой «Проверить без записи» и сверьте несколько заказов с кабинетом. Дата продажи берётся по дате создания заказа.
- Нужен интернет (без сети откроется оболочка, но данные не загрузятся и не сохранятся).
- Остаток по счёту расчётный (продажи чистыми + пополнения − расходы − снятия); начального остатка нет.
- Одновременное редактирование одной записи: побеждает последнее сохранение.
